# Decisions

Short log of decisions that shape the project. Newest first.

| Date | Decision | Reason |
|---|---|---|
| 2026-10-18 | "Organize" renames the folder (folder format) and the files (file formats) together; the folder keeps its parent (root folder), and the folder is renamed even when renaming files is off. Subtitles, NFO and "-thumb" art next to a video follow it; loose subtitles in a movie folder (e.g. Subs/2_English.srt) get the movie's name with language and flags. Items with a conflict (target exists, another item owns the folder, path longer than 259 characters on Windows, name over 255 bytes elsewhere) are skipped, never half-done | The owner's 0.2 imports kept release folder names; Radarr's Organize only renames files, which leaves those folders. Skipping conflicts keeps a run of hundreds of items safe |
| 2026-10-18 | Organize works item by item: the folder is renamed first, then the files inside; when a step fails the done steps are reversed. Case-only changes go through a temporary name; a folder to another drive is copied completely before the source is deleted. Each run is logged (tables OrganizeRuns/OrganizeRunItems, migration 17) and the last run can be undone for 24 hours; logs older than 30 days are removed | Undo needs exact old and new paths; 24 hours covers "that was wrong" without undoing on top of later imports. One run at a time keeps the log and the progress simple |
| 2026-10-18 | The mass editor offers monitored, quality profile, root folder (move or only change the path) and remove; minimum availability, season folders, series type and tags are not offered | Those fields do not exist per item in StreamZH yet (minimum availability is global) |
| 2026-10-18 | Removing with "Delete files and folder" moves the whole item folder into the Media Management recycle bin (as "<folder>", "<folder> (2)" when taken) or deletes it when no recycle bin is set; a root folder is never deleted; an item whose folder cannot be removed stays in the library. The detail page's Remove uses the same endpoint (admins) | Like Radarr's delete dialog; the recycle bin cleanup task already handles whole folders |
| 2026-10-18 | Cutoff unmet uses the decision engine's rules: a file in the wrong language for the profile is always unmet (also with upgrades off); with upgrades on a quality below the cutoff or a missing dual-language track is unmet. File languages are normalised like the engine (no tag = original language) and the quality the import stored wins over the file name | The list shows exactly what a search would still replace; the engine fixes a wrong language even with upgrades off |
| 2026-10-18 | Movies store the earliest digital and physical release of any country from TMDB release_dates (Radarr's digital/physical release). Minimum availability "Released" uses the earlier of the two when known, else cinema + 90 days as before | Radarr's rule; a digital release a few weeks after the cinema no longer waits 90 days |
| 2026-10-18 | Calendar dates are TMDB days without a time or time zone: all-day events in the API and the iCal feed (VALUE=DATE). "Aired" and "missing" use the server's UTC day like the automatic search; a calendar request may send dates with an offset, which count as the day in that offset | TMDB has no air times; all-day events show on the right day everywhere, and Wanted, Calendar and the search agree on what has aired |
| 2026-10-18 | Wanted lists are built in memory (all movies and episodes, a few bulk queries) and paged and sorted afterwards; "last searched" is a small LastSearches table written by the automatic search, not columns on Movies/Episodes | A home library is a few thousand items; a separate table keeps the shared library tables untouched |
| 2026-10-18 | Wanted → Missing hides unmonitored items and not yet available movies / unaired episodes by default (filters show them); specials only when monitored. "Search all" uses the default filters and works out the list when the job runs | Like Radarr/Sonarr; a queued job does not search items that got a file meanwhile |
| 2026-10-18 | iCal feed at /api/v1/calendar/feed.ics signs in with ?apikey= (any API auth works); tags=movies/series instead of Sonarr's tag ids; the link is shown to admins only. First day of week is a UI setting (Monday by default) | Calendar apps cannot send headers or cookies; StreamZH has no tags yet; the API key is admin-only |
| 2026-10-18 | Windows service through StreamZH's own `ServiceBase` session (`src/StreamZH.Host/Service`), connected once per process before the first run, instead of `UseWindowsService()`/`WindowsServiceLifetime`; each run gets a host lifetime that stops the run, not the service. No event log provider: only an unhandled error (startup failure, crash) is written to the Application log | Microsoft's lifetime reports the service as stopped when its host stops, which breaks the in-process restart; normal logs belong in the log files, not in the event log |
| 2026-10-18 | Service settings: name and display name "StreamZH", delayed automatic start, recovery restart after 5 s, 10 s, then 60 s (reset after a day, also on an error exit code), LocalSystem by default, `-Account` for a user (the script grants "Log on as a service"). The install script lets the installing user start and stop the service (service DACL) and gives that user Modify on the data folder | Update-Local.ps1 must update the service from a normal PowerShell; console runs after the service must still be able to write files the service created |
| 2026-10-18 | The install script does not change Controlled folder access or the firewall unless asked (`-AllowControlledFolderAccess`, `-Firewall` for the port, private and domain networks only); it prints the exact command otherwise and lists mapped drives with their UNC paths | Both are security settings of the owner's PC; services cannot see mapped drives |
| 2026-10-18 | Linux: `tools/install-linux.sh` (also shipped in the linux packages) installs to `/opt/streamzh` (root-owned), data `/var/lib/streamzh`, system user `streamzh`, unit `Type=exec`, `Restart=on-failure`, `UMask=0002`, `ProtectSystem=full`, no `ProtectHome` and no sd_notify | Media often lives under /home; systemd's notify protocol treats STOPPING=1 as the end of the service, which the in-process restart would trigger. "Shutdown" exits 0 and stays stopped |
| 2026-10-18 | "Runs as" adds "systemd" (the parent process is systemd); Docker keeps priority, then Windows service (parent services.exe in session 0), else console | Detected once per process from facts that a restart does not change |
| 2026-10-18 | Docker: the container starts as root only to give `/config` to `PUID`:`PGID` (default 1654, the image's app user; recursive chown only when the owner differs) and runs StreamZH with `setpriv`; `UMASK` like linuxserver.io; `--user` still works. Health check with bash's /dev/tcp on port 9797 (no curl in the image) | Same variables as the linuxserver.io images NAS users know; no extra packages |
| 2026-10-18 | Activity lists page and filter on the server (download history, events, blocklist); only the queue filters and pages in the browser. Filters and page live in the URL (`q`, `status`, `import`, `type`, `range`, `event`, `indexer`, `page`); the page size (25/50/100/200, default 50) is remembered per browser and per list, not put in the URL | History tables grow without limit, the queue is loaded whole anyway. URL state keeps back/forward and links working; a page size is a viewer preference |
| 2026-10-18 | The search box matches every word anywhere in the title (case-insensitive LIKE with `%`, `_` and `\` escaped), so "dune part two" finds "Dune.Part.Two.2024"; at most 8 words. SQLite LIKE folds ASCII letters only | Release names separate words with dots; non-ASCII letters are rare in release titles |
| 2026-10-18 | Download history "Not imported" = completed with no import or an import that is queued, running or waiting; "Import failed" is its own state; failed downloads are never "not imported". The type filter takes the kind (movie, series, other, which includes custom categories of that kind) or a custom category name | Keeps the three import states apart; matches how categories are stored |
| 2026-10-17 | RSS sync is on by default every 60 minutes (Radarr's default; 0 = off, otherwise 10 to 120). One page of the newest releases per indexer, no paging back to the last release seen | Radarr users expect automatic grabbing; one page per hour is cheap on API limits. A gap during a long outage is closed by the Search buttons or the scheduled missing search |
| 2026-10-17 | Releases with hardcoded subs (HC, SUBBED, KORSUB …, Radarr's pattern) are rejected by default; tags can be whitelisted or the check switched off | Radarr's default; the only 0.6 indexer rule whose default changes what gets grabbed |
| 2026-10-17 | Release profiles like Sonarr v3 in their own table, limited to indexers and quality profiles (instead of Sonarr's tags). Preferred scores add up over all profiles and rank after quality, revision and dual language, before indexer priority and size. A higher score replaces a file of the same quality and revision when the profile allows upgrades, even past the cutoff; the file's score comes from its file name | Sonarr's order (preferred words after quality and language). StreamZH stores no scene name per file, so the file name is the best source |
| 2026-10-17 | Minimum availability is one global setting (no per-movie value yet): Announced, In cinemas (default, the old rule) or Released = TMDB release date + 90 days, plus an availability delay. Without a date the TMDB status decides as before. Applies to RSS, the missing search and search on add; the Search button ignores it | Radarr's fallback when no home release date is known; TMDB's digital and physical dates would need another API call per movie. Movies now store the TMDB release date (filled on add and refresh) |
| 2026-10-17 | Scheduled "Search for missing" is an expert option, off by default, every 6 to 720 hours; "Start search for missing" when adding is off by default and a checkbox in the add dialog. A season with several missing episodes is searched as a season, a single one alone | Radarr and Sonarr have no periodic missing search because it burns API hits; experts can still have it |
| 2026-10-17 | "Prefer indexer flags" (Radarr) is not offered | Newznab indexers send no flags; freeleech and similar are torrent-only |
| 2026-10-17 | Download categories are a table; "movies", "series" and "other" are fixed defaults (cannot be renamed or deleted) and keep today's folders; custom categories count as "other" for the import | Grabs and old downloads use the default names; a custom category has no library link anyway |
| 2026-10-17 | Duplicate detection compares the release name (letters and digits only) and a fingerprint of the NZB's article ids (not a hash of the NZB file); failed downloads never count as duplicates | The same release from two indexers has different NZB files but the same articles; a failed release must be grabbable again |
| 2026-10-17 | Scheduler: rules run when their minute passes; at startup the latest rule of each kind (queue, speed, server, category) from the last week is applied once, a startup "resume" only lifts a pause the scheduler made; "pause server" disables the server in the settings | Like SABnzbd after a restart, without overriding a pause the user made; disabling is visible where servers are managed |
| 2026-10-17 | Pre-check uses NNTP STAT on all articles (up to 50 at once) and fails the download when par2 could not repair what is missing; missing articles are not marked, the download fetches them normally | Same repair estimate as "abort hopeless", without downloading anything |
| 2026-10-17 | "Password-protected RAR" is detected from the first article of any RAR volume (RAR4 flags, RAR5 encryption header or file encryption record) | Every volume carries the headers; no need to wait for the whole first volume |
| 2026-10-17 | Not implemented from SABnzbd: Direct Unpack, article cache, disk-full check interval, Sorting, Notifications, script options | Articles are written in place out of order by all connections (7-Zip cannot unpack volumes still arriving, and par2 may rewrite them); the OS page cache does the article cache's job; free space is checked every second; StreamZH renames on import; notifications are a separate area |
| 2026-10-17 | Extra par2/7-Zip parameters are split into an argument list (never a shell), must look like options, and options for output folder, password, file lists and archive type are refused; executables are never moved to the completed folder at any post-processing level | No command injection and no way to bypass StreamZH's own folder and password handling |
| 2026-10-17 | The watched folder is polled (default every 5 s), files must be unchanged for 2 s, broken NZBs are renamed to *.nzb.failed | File system events are unreliable on network shares and Docker mounts; half-copied files must not be taken |
| 2026-10-17 | Settings → Connect is one "Connections" table for media servers (Plex, Jellyfin, Emby, Kodi) and notifications (Discord, Telegram, Pushover, ntfy, Gotify, Email, Webhook, Apprise); the type-specific settings are JSON driven by a field catalog in the backend, the UI draws the form from it | Same model as Radarr's notifications; a new service is one sender plus its field list, no migration |
| 2026-10-17 | Deliveries never block the import: events are queued, handled in order, sent one after the other per connection, network/timeout/429/5xx errors retried after 10 s, 1 min and 5 min; the last error is stored and shown as "Plex: unauthorized" in the list and the status window until the next success, test or save | A media server that is down must not stop the pipeline, but the user has to notice it |
| 2026-10-17 | On Health Issue/Restored compare the status-window warnings and errors every minute (after a 2-minute start grace), without failed downloads (own trigger) and the connections' own notices | No separate health-check system; the status window already is the list of problems |
| 2026-10-17 | Plex scans only the changed folder in the libraries whose locations contain it (after "Map paths from/to"), and all libraries of the type when none matches; Jellyfin/Emby get "Library/Media/Updated" with the folder, Kodi a VideoLibrary.Scan of the folder (skipped during playback unless "Always update") | Partial scans like Radarr; the full-scan fallback still works with a wrong mapping |
| 2026-10-17 | Email through MailKit (with SSL on connect for port 465), MailKit/MimeKit pinned with the patched System.Security.Cryptography.Pkcs | .NET's SmtpClient cannot do implicit TLS and is not recommended for new code |
| 2026-10-17 | Metadata writer "Kodi (XBMC) / Emby" (off by default) writes NFO files and artwork in Radarr's and Sonarr's names; NFO files carry a "Created by StreamZH" comment so only StreamZH's own NFO and thumb files are moved after a rename or deleted when the video is gone; release NFO files are kept as .nfo-orig; TMDB has no banners, so none are written | Users switching from Radarr/Sonarr keep their Kodi/Jellyfin setup; StreamZH never deletes files it did not write |
| 2026-10-17 | The web UI loads posters through /api/v1/mediacover/{size}/{file}: a redirect to the TMDB CDN by default, served from <data>/MediaCover with the "Local image cache" switch | Replaces "local image cache later"; one switch for privacy, default behaviour unchanged |
| 2026-10-17 | Certification country (default US) is a metadata setting; the TMDB details client returns the certification of that country for NFO files and the {Movie Certification} naming token | Same option as Radarr; German users want FSK ratings |
| 2026-10-17 | Rename movies and Rename episodes default ON (Radarr and Sonarr default off), with Radarr/Sonarr's default formats ("{Movie Title} ({Release Year}) {Quality Full}", "{Series Title} - S{season:00}E{episode:00} - {Episode Title} {Quality Full}"); only new imports are renamed, existing files only with "Rename files" | StreamZH creates the folders anyway and stores the quality of every imported file, so a clean name costs nothing; users who keep scene names switch it off |
| 2026-10-17 | Imported files get a MediaFileDetails row (quality, revision, languages, release group, release title) keyed by full path; the decision engine and rename read it before parsing the file name | Renaming must not lose the quality (Radarr keeps it in MovieFiles); a disk scan only sees names and sizes, so the details live beside the Movies/Episodes rows |
| 2026-10-17 | Completed download handling runs as a job per download ("Import …"); state per download in DownloadImports (queued, importing, imported, waiting, failed). A failed import keeps the files and shows in Activity → Queue "Waiting for import" and as a status-window notice until retried, imported by hand or dismissed | The engine must not wait for slow cross-drive moves; the user needs a clear reason and a retry, like Radarr's queue warnings |
| 2026-10-17 | Import checks: no samples (name/folder rule of the disk scan; no runtime check without ffprobe), the movie is the largest video file, episodes must be in the grab (Sonarr "was not grabbed"), not worse than the file on disk (rank, then revision; a wrong-language file may always be replaced), free space unless skipped (only counted when the files cross drives or are copied). Manual import skips the upgrade check | Same rules as Radarr/Sonarr's import specifications that make sense without media info |
| 2026-10-17 | Old files are replaced after the new file is in place (same name: the old one is set aside first and put back if the move fails); they go to the recycling bin or are deleted. Old multi-episode files stay while other episodes still use them | An import must never leave the library without a file |
| 2026-10-17 | Failed download handling: a failed download of a movie or episodes goes on the blocklist (new table), is removed from Activity with its incomplete files ("Remove failed", default on) and searched again ("Redownload failed", default on; a failed season pack searches the whole season) | Radarr/Sonarr defaults; the history keeps "Download failed", the blocklist keeps the reason |
| 2026-10-17 | Series type is not stored yet: daily format for releases named by air date, anime format for Japanese animation (TMDB genre Animation + original language Japanese); absolute episode numbers are not supported | Sonarr's series types need data StreamZH does not have yet; this covers the common cases |
| 2026-10-17 | "Change file date" offers None and Release date (movies: TMDB release date, fetched at import; episodes: air date); Radarr's "physical release" is left out | TMDB's primary release date is the only movie date StreamZH can get without extra requests |
| 2026-10-17 | One "Season folders" switch for all series (Sonarr has it per series) and the {label-{Token}} syntax for Plex ids/editions ({tmdb-{TmdbId}}, {edition-{Edition Tags}}) | No per-series settings yet; Plex users need these names |
| 2026-10-17 | Restart is in-process: Program.cs runs its whole startup again after the host stops (`goto start`, keeps the diff to Program.cs small); a new address that cannot be bound starts once more with the previous one | Works the same in a console, a future Windows service and Docker without relying on a supervisor or restart policy; a typo in the port must not take StreamZH offline |
| 2026-10-17 | Host settings (bind address, port, URL base, HTTPS with a .pfx) live in the database and are read before Kestrel is built; `--urls`, `ASPNETCORE_URLS` or a Kestrel section in appsettings win (except the URL base); `Urls` removed from appsettings.json, the Docker image's `HTTP_PORTS` is ignored | Same as Radarr's config.xml values with the command line on top; the settings page stays the one place to change them |
| 2026-10-17 | URL base: the server adds `<base href>` to index.html at runtime and the frontend build uses relative asset paths, so one build works at the root and below any URL base; pages opened outside the base are redirected to it; the proxy must not strip the path (like Radarr) | No rebuild per URL base, API, SignalR and static files all work under PathBase |
| 2026-10-17 | Authentication methods like Radarr: Forms (default), Basic, External (no sign-in, for a reverse proxy like CloudZH SSO; shown in the UI with a warning and a status-window notice); "Disabled for local addresses" also checks X-Forwarded-For/X-Real-IP/Forwarded so a proxy on the same machine does not open StreamZH to the internet; `--auth-method` overrides the stored method | Radarr hides External in config.xml; here it is visible but explained, and the command-line switch is the way back in |
| 2026-10-17 | Proxy and certificate validation apply through an `IHttpMessageHandlerBuilderFilter` (after each client's own setup, so the indexer client's own handler is covered), live without restart; with the proxy off the system proxy is used as before | All outgoing HTTP in one place; NNTP is not proxied |
| 2026-10-17 | Backups like Radarr (scheduled every 7 days, 28 days retention, manual ones kept); the zip holds the database (`VACUUM INTO`, consistent while running), the data-protection keys and backup.json; restore is checked (integrity, StreamZH tables, not newer than this version) and staged, then applied at the next start before the database opens; the old database is kept | Restoring under a running app with open connections is unsafe; keeping the old files makes a wrong restore reversible |
| 2026-10-17 | Updates: only "Check for updates" against GitHub releases of streamzh/streamzh (404 while private = "no update information yet") and honest instructions per runtime; no built-in updater yet | Do not fake an update mechanism |
| 2026-10-17 | Settings → UI stored per instance: short/long date format, time format (Radarr tokens) and relative dates; default "locale" keeps the browser format shown before; all date output goes through `lib/format.ts`. First day of week and theme are not offered yet (no calendar, no light theme) | No options without an effect |
| 2026-10-17 | Automatic search skips a movie or episode only while it is in the built-in download queue; the 12-hour "recently grabbed" rule stays only for the blackhole folder | A grab that went to the old NZB folder, failed or was removed must not block the Search button; the queue knows what is really downloading (like Radarr) |
| 2026-10-17 | StreamZH installs par2cmdline-turbo 1.5.0 and 7-Zip 26.03 itself (pinned official GitHub releases, SHA-256 checked, into `<data>/tools`), automatically at startup when missing and with "Install" in Settings → Tools; replaces the par2 download in Update-Local.ps1. par2cmdline-turbo replaces par2cmdline | Owner does not want to install tools by hand; the data folder is writable and survives updates. par2cmdline-turbo is much faster, has the same command line and is what SABnzbd uses |
| 2026-10-17 | Advanced mode like Sonarr/SABnzbd: simple view by default, one "Advanced" switch (remembered per browser) shows the expert settings, their labels in the warn colour; a save error on a hidden field switches it on | Most users never need timeouts or pipelining; experts find everything in one place without a separate settings page |
| 2026-10-17 | Usenet server "On failure" is one select: Skip (default, 5 min), Pause downloads (required: every fetch fails while the server is in back-off, its quota is used up or it failed for an article, so the engine pauses and nothing is marked missing), Ignore longer (optional: 30 min back-off, no status-window notice) | Same idea as SABnzbd's required/optional, but one choice instead of two exclusive checkboxes |
| 2026-10-17 | Articles per request (pipelining) defaults to 1, not SABnzbd's 2 | New pipelining code in the NNTP client; experts can raise it per server |
| 2026-10-17 | Server quota counts NNTP bytes in GB of 10^9 (as providers sell them) from when it is set or reset; used up = server skipped and a notice | A block account must not be overdrawn; the free-space setting stays in GB of 1024³ like the disk notice |
| 2026-10-17 | Download engine expert settings: minimum free space (1 GB), abort hopeless downloads (on), keep par2/archive files (off), tries per article (3) | The engine's former constants; defaults keep the old behaviour |
| 2026-10-17 | Built-in Usenet download engine is the default download client; "Blackhole folder" stays as an option for an external downloader | StreamZH replaces SABnzbd; the folder mode keeps SABnzbd usable during the switch |
| 2026-10-17 | par2 verify and deobfuscation in own C# code; repair with par2cmdline and unpacking with 7-Zip as external processes (par2 downloaded by Update-Local.ps1 on Windows; superseded: StreamZH installs both itself, see above) | Verify is needed for every download and must not depend on tools; repair and RAR unpacking are best left to the proven tools, not linked |
| 2026-10-17 | Recovery par2 volumes are only fetched when articles are missing (about 1.2× the missing data, all of them if repair still lacks blocks) | Saves bandwidth like SABnzbd |
| 2026-10-17 | Status window bottom right like CloudZH (running tasks + heads-up notices), Activity page with a pipeline per download | Owner wants to see at a glance what is happening |
| 2026-10-17 | Logo: letter corners of the wordmark softened (radius 1.5), gap reduced by a quarter to 0.24 | Owner's request: less angular, monogram and name closer together |
| 2026-10-17 | Logo refined: wordmark 70 % of the monogram, gap 0.32, monogram corners softened (radius 1.5), app icon monogram 60 % | Owner's choice after comparing variants; reads better next to the monogram and less angular |
| 2026-10-17 | Indexer catalog like Prowlarr: StreamZH ships indexer definitions (Usenet Newznab presets now, torrent definitions with the torrent engine in 1.0); replaces the earlier "no built-in indexer list" rule | Owner decision: adding an indexer should be as easy as in Prowlarr, Prowlarr no longer needed |
| 2026-10-17 | Prowlarr features built in: per-indexer query/grab limits, VIP expiry, additional parameters, indexer history, stats, search across all indexers, import from Prowlarr | StreamZH replaces Prowlarr completely |
| 2026-10-17 | Until the built-in download engine (0.5), "Grab" saves the NZB into a folder that SABnzbd can watch | Real downloads can be tested with 0.4 already; the folder becomes the engine's input later |
| 2026-10-17 | Failing indexers pause with escalating back-off (5 min up to 24 h), a success resets it | Same idea as Prowlarr; protects API limits |
| 2026-10-17 | Releases without a language tag count as the original language of the movie or series (from TMDB) | Same as Radarr; English scene releases carry no tag |
| 2026-10-17 | Ranking: quality first, then PROPER/REPACK, then dual language | Same order as Radarr without custom formats; a German.DL WEB-1080p does not beat a German Bluray-1080p |
| 2026-10-17 | A file in the wrong language is always replaced by a release in the profile language, even past the cutoff | A GermanSubbed or English file in a "Deutsch" profile is not finished |
| 2026-10-17 | Release parser: Sonarr episode patterns and Radarr movie patterns in one parser; clear SxxEyy wins, ambiguous patterns lose to a movie | Indexer searches mix both; names like "Blade.Runner.2049.2017" must stay movies |
| 2026-10-17 | Logo: same as CloudZH (monogram Z in front of H, Zurich red #C0202A, Outfit wordmark) with «Stream» in place of «Cloud» | StreamZH is part of the CloudZH family; one brand system, generator in `tools/brand` |
| 2026-10-17 | Quality and language ids identical to Radarr | Profiles and history can be imported from Radarr/Sonarr later (0.8) |
| 2026-10-17 | One quality profile model for all media types, with required language and "prefer dual language" | German scene releases (German.DL) are the main use case of the first user |
| 2026-10-17 | Default profile "Deutsch 1080p" in the test phase | Matches the owner's library; public 1.0 will default to "HD-1080p" with original language |
| 2026-10-17 | TMDB is the single metadata source for movies and series; each user brings their own free TMDB key | One source for both types, no proxy server to run; TVDB id is still stored for compatibility |
| 2026-10-17 | Removing an item from the library never deletes files; file deletion becomes an explicit option later | Safe default while the app is young |
| 2026-10-17 | Posters load directly from the TMDB image CDN; local image cache later | Keeps 0.2 small; cache needed for offline use and privacy |
| 2026-10-17 | Library import keeps existing folder names, nothing is moved or renamed | Lets users try StreamZH on a live library without risk |
| 2026-10-17 | Native packages for Windows, Linux and macOS like Sonarr/Radarr, plus Docker; no FreeBSD | Most home users run Windows or a NAS, not only Docker |
| 2026-10-17 | First test version: Movies + Series, Usenet only | Replaces the stack that runs on the home server today (Radarr, Sonarr, SABnzbd); fastest path to a real test |
| 2026-10-17 | Frontend: React + TypeScript + Vite | Largest ecosystem, same family as the Sonarr/Radarr UI |
| 2026-10-17 | Backend: .NET 10 / C# | Sonarr, Radarr and Prowlarr are GPL-3.0 on .NET 10, their parser code and tests can be ported directly |
| 2026-10-17 | Own engine built from scratch, not a UI over the existing *arr APIs | One database, one queue, built-in download engine without polling |
| 2026-10-17 | Repository private during the test phase, public from 1.0 | Build in peace, clean up history before release |
| 2026-10-17 | License GPL-3.0-only | Allows reuse of *arr code; others may build on it, also as a hosted service |
| 2026-10-17 | Separate repository from CloudZH, integration only through the HTTP API | Keeps the GPL away from the commercial CloudZH code |
| 2026-10-17 | Data access: Dapper + FluentMigrator, SQLite by default | Same pattern as the *arr apps, simplifies porting |
| 2026-10-17 | Default port 9797, data dir `/config` in Docker | Does not collide with Sonarr (8989), Radarr (7878), Prowlarr (9696), SABnzbd (8080) |
